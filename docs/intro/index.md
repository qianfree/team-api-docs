# 项目介绍

[Team-API](https://github.com/qianfree/team-api) 是一个**多租户大模型 API 网关 SaaS 平台**：统一接入 OpenAI、Claude、Gemini 等多家大模型供应商，对外提供 OpenAI 兼容接口，并内置计费、限流、监控和多租户管理能力。

一句话概括：**一个可以自己部署的「大模型 API 中台」** —— 下游对齐 OpenAI 协议，上游聚合各家模型，中间把额度、计费、调度、监控这些「运营级」能力全部做好。

## 为什么需要 Team-API

团队直接使用大模型 API 时，通常会陆续撞上这些问题：

| 常见痛点 | Team-API 的解法 |
|---------|----------------|
| 上游账号分散在多家供应商，Key 管理混乱 | 渠道统一配置、统一监控、统一调度，多家供应商集中管理 |
| 应用被绑定在某一家模型厂商 | 对外只暴露 OpenAI 兼容接口，切换 / 替换上游对应用零改造 |
| 团队与项目的 AI 成本算不清、控不住 | 三层额度模型 + 实时计费引擎，成本核算到成员、项目、每一把 Key |
| 想对外提供模型服务，缺多租户与计费体系 | 行级多租户隔离 + 套餐 / 钱包计费，开箱即用的 SaaS 架构 |
| 上游故障导致业务中断 | 智能渠道调度 + 自动故障转移，渠道健康实时监控 |
| 出了问题无从排查 | Request ID 贯穿全链路，请求日志、操作审计、监控告警三位一体 |

## 核心能力一览

- **多租户架构** —— 行级数据隔离，管理后台与租户控制台双独立用户体系
- **适配多家大模型供应商** —— OpenAI、Claude、Gemini、DeepSeek、通义千问、智谱、Ollama 等
- **OpenAI 兼容 API** —— 现有应用替换 `base_url` 与 `api_key` 即可无缝迁移
- **智能渠道调度** —— 优先级 / 权重路由、自动故障转移、健康监控、渠道亲和
- **三层额度模型** —— 租户钱包 → 项目预算 / 成员额度 → Key 额度
- **实时计费引擎** —— 预扣 → 转发 → 结算 → 退款，高并发下资金安全
- **双控制台** —— 管理后台（平台运营）+ 租户控制台（终端用户）
- **全链路可观测** —— 请求日志、操作审计、监控告警，Request ID 全链路追踪

各项能力的详细说明见[功能特性](/intro/features)。

## 适用场景

### 企业内部 AI 平台

统一收口各团队的大模型调用：每个部门或项目组对应租户 / 项目，额度与预算逐层下发，AI 成本可以直接核算到项目与成员；管理员在管理后台集中管理渠道、定价与告警，员工在各自控制台自助使用，互不干扰。

### AI SaaS 创业团队

想以「卖模型服务」为业务的团队，可以直接复用 Team-API 的多租户、套餐、钱包与计费体系，把精力放在产品与获客上，而不必重复造配额与计费轮子。支付模块（Easy Pay）已内置，套餐购买、钱包充值开箱即用。

### 个人 / 小团队

聚合手头的多个上游账号（包括本地 Ollama），一个 OpenAI 兼容入口按需调度、自动故障转移；支持单文件二进制部署，资源占用小，一台小机器就能跑。

## 技术栈

| 层级 | 技术选型 |
|------|---------|
| 后端框架 | Go 1.25 + [GoFrame v2](https://goframe.org/) |
| 数据库 | PostgreSQL 15 |
| 缓存 | Redis 7 + 内存缓存（双层） |
| 数据库迁移 | [Goose](https://github.com/pressly/goose) |
| 管理后台前端 | Vue 3 + Vite + Arco Design Vue + TailwindCSS |
| 租户控制台前端 | Vue 3 + Vite + TailwindCSS |
| 对象存储 | S3 兼容存储 / 阿里云 OSS / 腾讯云 COS |
| 前端包管理 | [bun](https://bun.sh/) |

整体分层与设计取舍见[架构概览](/intro/architecture)。
